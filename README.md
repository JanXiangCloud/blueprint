# 案 A・案 B の特徴比較

## 表 1　案 A（集中型）の特徴

| 観点 | 内容 |
|---|---|
| 構成 | 社員 PC には C# WPF クライアントのみを置き、Agent はサーバー上で動作する |
| Agent Core | サーバー上に 1 つだけ存在し、全ユーザーで共用する |
| 会話・状態 | サーバーの共有ストアに保存する |
| 認証情報 | LLM の API キー、SharePoint・SQL Server への接続情報はサーバーにのみ置く |
| データ接続 | サーバーから MCP 経由で SharePoint・SQL Server に接続する（サーバーにのみ開放） |
| 更新 | サーバーを更新すれば全ユーザーに即時反映される |
| 監査 | 質問・検索文書・ツール呼び出し・回答を一連のトレースとしてサーバーに記録する |
| 端末間の共有 | 別の PC でサインインしても会話を続けられる |
| ローカル資源 | PC 上のファイルやアプリには直接アクセスできず、ユーザーが手動で添付する |
| 可用性 | サーバーやネットワークの障害時は全ユーザーが利用できない |
| 必要な基盤 | Agent サーバーの構築・運用（冗長化、監視、バックアップ） |

## 表 2　案 B（分散型）の特徴

| 観点 | 内容 |
|---|---|
| 構成 | 各 PC に C# WPF クライアントとローカル Agent サービス（.NET 常駐）を置く |
| Agent Core | PC ごとに 1 式ずつ存在し、それぞれ独立して動作する |
| 会話・状態 | 各 PC 内にのみ保存し、PC 間では共有されない |
| 認証情報 | LLM の API キーやデータ接続情報を各 PC に保管する |
| データ接続 | 各 PC から MCP 経由で SharePoint・SQL Server に接続する（全 PC への開放、または中央 MCP サーバーが必要） |
| 更新 | Agent・プロンプトを全 PC へ配信する必要があり、バージョンが揃いにくい |
| 監査 | ログが各 PC に分散するため、回収・集計が必要 |
| 端末間の共有 | 別の PC では会話を続けられない |
| ローカル資源 | PC 上のファイル・Excel・Outlook を直接操作できる |
| 可用性 | 自社サーバーの障害の影響を受けない（LLM API と外部サービスへの接続は必要） |
| 必要な基盤 | 更新配信、API キー配布・失効、ログ回収、ナレッジ同期の運用基盤 |

## 表 3　案 A と案 B の比較

● 有利　◐ 条件付き・中程度　○ 不利

| 比較項目 | 案 A 集中型 | 案 B 分散型 |
|---|---|---|
| 更新・配布 | ● サーバーのみ更新 | ○ 全 PC へ配信 |
| 認証情報の管理 | ● サーバーに集約 | ○ 各 PC に分散 |
| SharePoint の文書権限 | ● サーバーで一元適用 | ○ ローカル索引に越権リスク |
| SQL Server のアクセス制御 | ● サーバーにのみ開放 | ○ 全 PC への開放が必要 |
| 監査・追跡 | ● 一連のトレースを集約 | ○ 回収・集計が必要 |
| PC をまたぐ会話の共有 | ● 標準で可能 | ○ 同期の仕組みが別途必要 |
| ナレッジの一貫性 | ● 索引は 1 つ | ○ PC ごとのコピーが不一致になりうる |
| ローカルファイル・アプリ連携 | ○ 手動で添付 | ● 直接操作 |
| 自社サーバー障害の影響 | ○ 全員が利用不可 | ● 影響なし |
| 開発の複雑さ | ● 低い | ◐ 中程度 |
| 運用の負荷 | ● サーバーのみ | ○ 全 PC が運用対象 |
| PC の性能要件 | ● 低い | ◐ 常駐サービス + ローカル索引 |
